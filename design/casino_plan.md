## 2. 場所と建築

### 2.1 既存店舗システムの流用可否
既存の店は「街路ファサード＋真下 y=-40 に 18×12m の内装室」で、`main.gd` の `in_shop`（`city.shop_sites` のインデックス）で出入り・落下救済の免除・カメラ距離変更を処理している。カジノはこの仕組みの**拡張として実装する**（新規の出入りシステムは作らない）：
- `shop_sites` に `kind: "casino"` のサイトを1件追加し、内装ビルダーだけ専用の `_build_casino()` に差し替える。
- ただし内装規模が全く違う（下記）ため、`in_shop` の「店内では落下救済免除」「店内カメラ距離」は流用しつつ、カジノ側はサイト定義に `cam_dist` と `interior_center` を持たせる小変更を行う。
- 店内装が y=-40 の既存6店と干渉しないよう、カジノ内装は **y=-60** に置く（20mの垂直分離。XZが重なっても物理的に干渉しない）。入口ドアのXZ直下に内装中心を置く既存作法は維持する。

### 2.2 入口の場所
推奨：**広場の南東側**。理由：広場は街の中心で集客導線が自然、既存店（ヒール堂＝東、ネオンマート＝西、電脳店＝南）と競合しない角。ファサードは店の7.5mパネルではなく、幅 ~24m・高さ ~9m の専用グランドエントランス（金ガラス＋ピンク縦ネオン＋「CASINO NEON PEARL」大型サイン＋金属探知ゲートの予告アーチ）。

## 4. ゲームルール実装仕様

共通原則：
- 乱数は Godot の `RandomNumberGenerator`（シードは実行時）。結果は**先に乱数で決め、演出はそれに合わせる**（実機のビデオゲーム方式）。イカサマ補正は一切なし（勝率は実物どおり＝カジノ側がハウスエッジで長期的に勝つ設計、と正直に仕様化する）。
- ベット〜決済は `main.gd` の `money` ではなく**チップ残高（§5）**に対して行う。ゲーム中UIは CpUi パネル。
- 各ゲームは「着席→プレイ→離席」の状態機械。着席中はキャラクターを卓前の固定位置＋固定カメラ（店内カメラより近い距離）に移す。
- ロジックは UI と分離した純粋クラス（`casino/roulette_logic.gd` 等）として書き、headless 単体テストで検証可能にする（§9）。

### 4.1 ルーレット（ヨーロピアン・シングルゼロ）

### 4.2 ブラックジャック

- ルール：ディーラーは**ソフト17を含む全17でスタンド**（S17）。ブラックジャック配当 **3:2**。ディーラーのホールカードは最後にオープン（米国式）。ディーラーのアップカードが A のとき**インシュランス**提供（配当2:1、ベット額の半分まで）。
- プレイヤー選択肢：ヒット / スタンド / ダブルダウン（最初の2枚のみ、任意の点数、追加カード1枚）/ スプリット（同数ペア。スプリット後の手は最大4手まで、スプリットAは1枚のみで21はBJ扱いにしない、ダブルはスプリット後も可〈A除く〉）。サレンダーは実装しない（仕様として明記）。
- ディーラーAI：上記ルールの機械的適用のみ（17未満ヒット、17以上スタンド、バースト判定）。
- 進行：ベット→配牌（プレイヤー2枚表、ディーラー1枚表1枚裏）→（BJ即時判定）→プレイヤー各手の行動→ディーラーオープン→精算。着席1人プレイ＋両隣に客NPCのダミーハンドは回さない（テンポ優先、NPCは見た目のみ）。
- UI：カードはアトラスから描画。合計点（ソフト/ハード両表記、例「7/17」）を常時表示。

### 4.3 ポーカー（テキサスホールデム、CPU対戦）
- 形式：6人卓（プレイヤー＋CPU 5人）、ノーリミット。ブラインド **SB 25 / BB 50**、バイイン 2,500（100BB）固定、スタックが 500 未満で自動リバイ確認（チップ残高から）。
- 流れ：ボタン回転→ブラインド→プリフロップ（BBの次から）→フロップ→ターン→リバー、各ストリートでベットラウンド（フォールド/チェック/コール/ベット・レイズ、ミニマムレイズ＝前回レイズ幅、オールイン可）。
- ハンド評価：7枚から最良5枚を選ぶ完全な評価器（ロイヤル〜ハイカード、同ランク時のキッカー比較まで正確に）。サイドポットは**実装する**（オールイン額差の精算を正しく行う。ここを簡略化すると「本物」と言えない）。
- CPU AI：3タイプの性格（ルーズパッシブ／タイトアグレッシブ／バランス）を席ごとに割当。判断は「ハンド強さ（プリフロップはホールカード評価表、以降はアウツ概算＋ポットオッズ）×性格係数×小さなランダム」で行う簡易ヒューリスティクス。読み合い（ブラフ頻度低め）も性格で持たせる。思考時間 0.6〜1.4 秒でテンポを保つ。
- テーブル表示：ポット額、各席スタックとアクション履歴（最終アクションのラベル表示）、勝者ハイライトとハンド名表示（日本語：例「フラッシュ」）。
- 離席時：スタックはチップ残高に戻る（現金化は cage で行う二段構えを維持）。

### 4.4 スロット（Phase 4・簡易）
3リール×1ラインの古典式。ベット 25 固定、絵柄配当表を筐体に表示。カジノの賑やかしが主目的で、仕様は Phase 4 で詰める。

## 5. 経済システム

- 交換レート：**€$1 = チップ1**（等価）。両替ではなく「チップ購入」として cage で行う。
- チップ denominations（実カジノの標準色）：
  | 額面 | 色 |
  |---|---|
  | 25 | 緑 |
  | 100 | 黒 |
  | 500 | 紫 |
  | 1,000 | 黄 |
  | 5,000 | ピンク |
- フロー：cage で「購入」UI（金額プリセット 500 / 1,000 / 2,500 / 10,000＋任意額）→ `money` から引かれ `chips` に加算（内訳は自動で大きな額面から両替表示、保持は総額 int で管理し内訳は表示用計算）。換金は全額一括 or 任意額を cage で `money` に戻す。
- テーブルバイイン：着席時にチップ残高から卓へ持ち込み額を指定（BJ/ルーレットは残高直引きでも可とするが、ポーカーはスタック制のため §4.3 の通り）。
- データ保持：`main.gd` に `chips: int` と `casino_stats`（総ベット/総勝ち/NEON CIRCLEポイント）を追加。既存の所持金同様セーブは持たない（現行仕様に合わせる）。
- 破産時：チップ0かつ所持金が最小バイイン（100）未満なら cage が購入を断り、インフォ係が「JOBキオスクで稼ぐといい」と案内する（既存の仕事システムへの誘導）。**借金・貸付システムは作らない**（ギャンブル依存の助長を避ける線引きとして明記）。死亡時の手数料（既存 `mini(50, money)`）はチップに触れない。
- NEON CIRCLE：総ベット額 100 ごとに 1pt。ランク：1,000pt で SILVER（バーで1杯無料/日）、10,000pt で **GOLD＝VIPサロン入場可**。ポイントの現金価値は持たせない（景品交換は将来拡張）。

## 7. UI方針（CpUi準拠）

- 全パネルは CpUi の切り欠きパネル＋シアン縁＋赤/黄アクセントで統一。カジノ固有色として金の見出しを追加色に許可（CpUi に `gold` バリアントを足す）。
- 共通：着席すると画面下部にゲーム専用パネル、上部にチップ残高と卓のミニマム表示。離席ボタンは常に右上（長押し不要・誤タップ防止に確認なしで即離席、ベット中ハンドは継続不可＝フォールド扱いの注記を出す）。
- ルーレット：画面右半分にレイアウトパネル（フェルト印刷と同一図版を UI 用に流用）、下に denom 選択チップ列、SPIN / CLEAR / REPEAT ボタン。3D側はホイール拡大カメラ。
- ブラックジャック：カードは画面中央に実物大で並べる 2D 表示（3D卓上のカードは演出用に小さく置く併用も可だが、視認性優先で 2D を正とする）。アクションボタンは大きな4ボタン（HIT/STAND/DOUBLE/SPLIT）。
- ポーカー：自分のホールカードを大きく、コミュニティカード中央、各CPUは卓周囲の小パネル（名前/スタック/状態）。アクションは FOLD / CHECK or CALL（額表示） / RAISE（スライダー＋プリセット：ポットの 1/2, 1, 2倍, オールイン）。
- cage：購入/換金の金額プリセットボタン＋所持金/チップ残高の併記。レート表示「€$1 = 1 CHIP」。
- タッチ前提：全ボタン最小 56px、ベット確定はベットボタン明示（タップ即確定にしない箇所：ルーレットのチップ配置は置く→SPINで確定）。

## 8. 技術メモ（このプロジェクトの制約）

- **配布形式**：モデルは ModelBlob `.tres`（push 1回 ~3MB 制限）。カジノモデル一式は §3 の3分割を基本とし、1ファイルが超える場合は卓ごとに再分割。テクスチャ JPG は TextureLoader の Blob 経由（`.b64`/loose json は pck に入らない既存の教訓どおり）。
- **公開版は Blob 経路**：検証は必ず `.glb` を退避して Blob 経路を強制する（v5.2 の教訓）。ローカルの editor import で見て終わらせない。
- **llvmpipe 検証環境の罠**：`emission_texture`/強い emission は白飛び、`uv1_scale ≠ 1` は非triplanarで化ける。シャンデリアやスロット画面の発光は控えめ＋unshaded 変換は `model_loader._repair_materials()` の作法に従う。Xvfb 写真は実機より暗い/淡い前提で判断する。
- **内装の光**：カジノ内装は y=-60 の閉鎖空間。月光（方向光＋90m影）は地形に遮られる想定だが、**内装に影/光が漏れるかは Phase 1 で最初に確認**する。内装照明は OmniLight を多用せず、発光マテリアル＋少数の Omni（ピット2、バー1、VIP1 程度）＋環境光で組む（Compatibility/Web の fps 対策）。店内は既存店と同じく「常時夜の室内」としてライティングを固定する。
- **当たり判定**：内装の壁/卓は既存店と同じく `_box(..., true)` の静的コリジョン方式。卓に近づいたら着席トリガー（`interact()` の距離判定に casino 分岐を追加）。
- **既存システムとの接続点**：`main.gd` の `interact()` 優先順位（店内ブロック→ドア→…）にカジノ分岐を差し込む位置を実装時に確認。落下救済は `in_shop >= 0` で免除される既存条件にカジノも含める（casino サイトも shop_sites に入るので自動で効く想定だが要確認）。ミニマップは内装を描かない既存仕様のまま（カジノ内ではマップが街を示すが、店も同じなので許容）。
- **客NPCの着席問題**：Quaternius 系クリップに座りポーズが無い。Phase 1 の PDCA で「スツール＋腰高さオフセット＋Idle」が破綻しないか写真確認し、ダメなら全員立ち配置に倒す（判断を先送りしない）。
- **パフォーマンス**：内装は街と同時描画されない位置（地下）だが、描画カリングは距離ベースなので地上の街も描かれる可能性がある。内装に入ったら街側の高コスト物の visibility を落とす既存店の扱いを確認し、必要ならカジノ入場時に NPC（街の歩行者）の処理を止める等の間引きを検討。ドローコール実測を Phase 1 の完了条件に入れる。
- フォント：日本語表示は既存 jpfont（CI で取得）経由。カードのスート記号（♠♥♦♣）がフォントに含まれるか Phase 2 までに確認し、無ければアトラス画像で描く（UI のカードは画像描画が正解）。

### Phase 2：ルーレット
- ホイール（実配列）＋卓＋レイアウト印刷、ベットパネル UI、スピン演出
- 完了条件：全ベット種の配当テスト合格（§テスト）。

### Phase 3：ポーカー＋VIP
- ポーカールーム稼働（評価器・サイドポット・CPU AI）、VIP サロン解放（NEON CIRCLE）、VIP 卓（高額 BJ/ルーレット）
- 完了条件：評価器の網羅テスト、CPU のみで 200 ハンド自動対戦して破綻（スタック負数・ポット不一致）ゼロ。

### Phase 4：スロット＋仕上げ
- 簡易スロット、客NPC 増員、サーバー巡回、演出（シャンデリア回転、画面アニメ）

### テスト計画（既存スイートを壊さない）
- **ロジック単体（headless）**：`tests/casino_logic_test.gd`
  - BJ：デッキ構成、点数計算（ソフト/ハード）、ディーラー S17、3:2 精算、スプリット/ダブルの精算ケース集

- **ステージング書き出し**：リポジトリファイル一式での Web export が 0 エラー、pck のファイルテーブルに casino の tres が含まれること。
